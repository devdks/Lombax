# Lombax design foundations

These guides document four parts of making a Lombax entry. Catchment is the first worked example. Use the guides with the repository’s [entry and release instructions](../AGENTS.md).

| Part | Question | What the next part receives |
| --- | --- | --- |
| [Purpose](purpose.md) | What should the visitor be able to understand or do? | A specific situation, an obstacle, and a way to tell whether the entry helps. |
| [Concept](concept.md) | What interaction makes that possible? | The subject’s rules and a worked example showing how a visitor’s action changes the outcome. |
| [Design](design.md) | How will the visitor perceive and use that interaction? | A composition and visual language that make the action, evidence, and consequence legible. |
| [UI](ui.md) | Does the built entry deliver that experience? | A working entry and evidence from trying it in the vault on different screens and with different inputs. |

## Where to start

Start with [Purpose](purpose.md) when Lombax is free to propose an idea. When the owner brings a concept, start with the [supplied-concept path](concept.md#when-the-owner-brings-the-concept). It carries the premise forward and captures the purpose and implementation decisions the rest of the work needs.

Keep the handoffs short. A sentence, a worked example, or an annotated sketch can be enough. Keep the visitor’s goal and the decisive example visible through the build so that refinements can be tested against them.

## How the parts improve each other

- If the answer would make little difference in the visitor’s situation, revisit the **purpose**.
- If changing the input never reveals a meaningful difference or teaches the visitor why it occurs, revisit the **concept**.
- If the result is correct and the visitor cannot connect it to what they did, revisit the **design**.
- If the relationship is clear in the sketch and breaks on a real device or input method, revisit the **UI**.

## The quality bar

Masterpiece-level work is the ambition. A finished entry earns its place through a worthwhile purpose, an interaction the subject makes possible, and a polished experience that visitors can use.

## When to update the guides

Update a guide when we’ve put a new idea into practice in an entry and can point to how it brought the work closer to that ambition. In the relevant guide, record what changed, what it improved, and where the lesson could help again. Link to the entry so we can revisit the evidence as the guides evolve.
